公式ドキュメントは、Grok Bot に任せやすい仕事として 8 つの役割を挙げています。どれも共通して、**何を調べ、何を返し、何をしてはいけないか**がはっきりしています。以下は各役割の要点を日本語でまとめたものです（公式の最初のメッセージ例は原文を参照してください）。

## 8 つの役割

| 役割 | 任せること | 必ず書く「しないこと」 |
|---|---|---|
| 営業アウトバウンド | CRM の一覧から 25 社を調べて理想顧客像と照らしてスコア付けし、1 社あたり最大 3 人の連絡先とメール・LinkedIn の文面案を作る | 送信やシーケンス登録はしない。進行中の相手は除外する |
| タレントスカウト | 募集要項の必須条件に合う候補者を 20 人探し、根拠つきで並べ、個別の連絡文案を作る | 応募管理システムにいる人は除外。誰にも連絡しない |
| 広告運用 | キャンペーン別の費用と成果を予算・目標 CPA と比べ、配分変更を数字つきで提案し、Slack 用の報告案を書く | 予算は変えない。メッセージも送らない |
| 経費管理 | 経費システムと規程から週次サマリーを作り、受信箱の領収書と突き合わせ、不備や規程違反を担当者ごとに指摘する下書きを作る | メッセージ送信や精算の変更はしない |
| プロダクト性能 | リリース後のチェックアウト遅延をダッシュボードとトレースで調べ、原因候補を事実と仮説に分けて報告する | アラートや本番設定は変えない |
| バグ再現 | バグ報告をステージングで新しいテストアカウントを使って再現し、手順・期待値・実際の挙動・スクショ・環境をまとめる | 本番の顧客データは使わない |
| アカウントヘルス | 利用状況・問い合わせ・更新時期・関係者の動きを合わせて、注意すべき顧客を根拠つきで順位付けする | 顧客への連絡や CRM の編集はしない |
| 秘書（Chief of staff） | 受信箱・カレンダー・議事録などから、優先事項ドキュメントに関係するものだけを、出典・理由・次の一手つきで返す | メッセージ送信や会議の変更はしない |

このサイトでは、いくつかの役割を日本語の最初のメッセージつきで[プロンプト](/prompts/)にまとめています。マーケットプレイスで公開されている既製の Bot は[ボット](/bots/)で日本語で紹介しています。

## 依頼の組み立て方

公式の例から読み取れる型は次のとおりです。

1. **入力を指定する**：どの CRM ビュー、どのダッシュボード、どの規程か
2. **量と基準を決める**：「25 社」「20 人」「最大 3 人」のように数で区切る
3. **成果物の形を決める**：レビュー用リスト、短いレポート、下書き
4. **禁止事項を最後に書く**：送信しない、変更しない、本番データを使わない

この型は[依頼文の基本テンプレート](/prompts/request-template/)と同じ考え方です。まず読むだけ・下書きだけの仕事から始め、送信や変更は承認の後ろに置くのが安全です（[セキュリティ](/docs/security/)も参照）。
